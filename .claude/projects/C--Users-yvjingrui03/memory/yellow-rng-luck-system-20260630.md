## 黄色流派方向修正

原计划「翻面 + RNG」→ 翻面挂起（机制不成熟、缺乏跨色联动）。**确定方向：「RNG + 概率操纵 + 好运数」**。

**Why**：概率是开放系统，红蓝绿都能吃黄牌的概率加成，不需要新系统。翻面是封闭系统，只有黄色能玩。

**How to apply**：黄色运算牌保留现有 15 张的概率框架（20001-20015），补 2-3 张 meta 概率牌和连锁触发牌。黄色王牌围绕好运/霉运计数器设计变现机制。

## 好运数系统（已实现）

`GameData.gd` 新增：
- `lucky_count: int` — 全局好运次数（chance() 成功 +1）
- `unlucky_count: int` — 全局霉运次数（chance() 失败 +1）
- `chance(pct)` 自动累加，无需各效果脚本修改
- `reset_luck()` — 每局重置

## 已验证的设计方向

1. **连锁触发**：概率判定成功时，邻居也掷一次骰子。字段排列产生意义。
2. **保底机制**：第 N 次概率判定必定成功。配合主动王牌拖放时机。
3. **概率转换**：回合内所有 % 累计值 / 50 → 初始底数 +1。
4. **分裂判定**：一次骰子拆两次，取更好结果（视觉 = 双骰）。
5. **概率反射**：失败的骰子顺延给右侧牌。

## 待设计的卡牌点子

### 运算牌
- **清算日**：好运数达到 X → 底数 +好运数。结算清零。
- **厄运转移**：霉运数达到 X → 转化为费用。
- **幸运兔脚**：右侧牌下一次概率必定成功（不掷骰子直接 lucky++）。
- **翻倍或归零**：50% 好运数翻倍 / 归零。好运 >5 时 80% 翻倍。

### 王牌
- **运气银行**：每回合末存储好运数。可用储备替换任意判定为必定成功。
- **霉运转运**：每累计 5 霉运 → +1$ + 初始底数 +1。
- **幸运爆发**：好运数 ≥10 → 本回合所有判定必定成功。
