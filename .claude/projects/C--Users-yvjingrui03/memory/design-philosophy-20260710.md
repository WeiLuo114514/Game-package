# 设计哲学与职业反思（2026-07-10）

## 核心设计框架

**简单算术魔法的基因图谱**：
- STS 的手牌系统（效果驱动、卡牌即操作单元）
- 小丑牌的 Joker 机制（被动增益、乘法引擎）
- 自创的运算规则 + 位置博弈（核心差异化）

**风险-收益结构**：
- 乘法是「稳定的锚」（底仓，安全收益）
- 其他符号（除法、减法）是「风险筹码」——玩家主动承担风险换取高回报
- 决策不再是「哪张牌最强」，而是「我赌得起这张牌吗」

**王牌 vs Joker 的定位差异**：
- Balatro 的 Joker：ROI 压力大，胜负集中在商店 + RNG
- 算术魔法的王牌：辅助决策系统，帮玩家博上限或稳下限，不强绑定 Build
- 结果：决策压力分散在商店和局内多个系统，容错率更高

**迭代哲学**：
- 好设计不是白板上画出来的，是迭代中「长」出来的
- 设计者的角色不是规划者，是在每一轮选择「保留什么、砍掉什么」
- LocalThunk：「Balatro 也不是一开始就设计好的，是迭代了无数版才出来的」

## 项目起源

最初只是「小丑牌的卡牌交互比较有意思」，做了一个红牌堆 + 五个槽位 + 七个手牌的原型。参考旧案文件「算了吧？plus」（Documents 目录下）。当时完全没有「这会是代表作」的想法，纯粹出于好奇和好玩。

## 面试叙事策略

- **30 秒版本**：「算术魔法是 STS 的手牌系统 + 小丑牌的 Joker 机制 + 自创的位置博弈。」
- **诚实比华丽更有力**：「这个系统不是一开始就想好的，是一轮一轮迭代自己长出来的。」
- **区别化**：「Balatro 的胜负集中在商店和 RNG，算术魔法把决策压力摊到每一张牌、每一个槽位。」
