## 燃尽（原焚身）重做

### 新效果
> 若本牌至少受到 {threshold} 个加成效果，则再次触发左侧牌的效果。固有【消耗】标签。

- ID 10018，×2 底数，2 费，品质 2
- L1: threshold=2，L2: threshold=1
- 核心套路：加法在前 → 燃尽 → 红番二，加法在前 buff 燃尽 + 红番二后，燃尽让加法在前插队再触发一轮

### 设计迭代
- 最初方案：回手 + 永久底数 +1/2 → 18 关累乘失控，否决
- 方案 A：固定值传导（右侧 × 牌 +2/+3）→ 太简单
- 方案 B：底数传导 → 超模（乘法版星火）
- 最终方案：再触发左侧牌效果 → 生态位精准（×→× 链式互动空缺），操作空间大

### 实现方式
- 使用新增的 `bonus_requeue` 机制（非直接调用 left_card.apply()）
- 左侧牌通过 settlement_queue 插队，完整重播效果动画

## bonus_requeue 插队系统

### 新增文件/代码
- `GameData.gd`：`bonus_requeue: Array` 队列
- `PlayField.gd`：`_build_settlement_context()` 清空、`_handle_post_effect_variants()` 检测并插队（is_bonus: true，不跳 apply）

### 与 settlement_requeue 区别
- settlement_requeue：skip_effect=true，只重新参与数学计算（再放送等）
- bonus_requeue：is_bonus=true，完整重播动画 + 重新 apply()（燃尽等）

## 命名变更
- 焚身 → 燃尽（含文件名、CardConfig、DeckConfig、translations.csv）

## Bug 修复

### 临时魔法/消耗魔法激活后效果未生效
- 根因：标签系统 v2 重构（7月3日）时，`magic_apply_temporary.gd` 和 `magic_apply_consume.gd` 第 7 行守卫从「无标签才允许」误改为 `not target.has_tag(EXCLUSIVE)`
- 修复：改为 `if target.has_tag(TEMPORARY): return false` / `if target.has_tag(CONSUME): return false`（已有则拒绝重复打标）

### 燃尽兼容性验证
- 触发型效果（ON_DISCARD_CARD / 手牌 ON_SETTLE_STEP）的 `apply()` 默认返回 false（BaseEffect），被燃尽二次调用时无 Crash，只是无效果
