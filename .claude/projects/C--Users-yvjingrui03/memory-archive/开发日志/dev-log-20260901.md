# 开发日志 2026-09-01

## 今日改动

### 1. 王牌批量效果「飘字 + 动画」串行同步（核心，BaseWildEffect.gd）
- **问题**：批量型王牌（连锁引爆 1001 / 你先别急 L9001 / 红灯 L9005 / 警戒线 L9006 / 蓝色忧郁 L9007）对多张运算牌效果一次性全部生效（所有卡同时播数字滚动动画），但飘字是逐张从左到右（0.6s 间隔）→ 二者脱节。
- **方案**：新增静态辅助 `apply_card_effects_serial(cards, apply)`，把「单张牌改数据 + 飘字 + 粒子 + UI 刷新」打包成**一个** `SettlementSequencer.AnimationRequest`（execute 改数据 / animate 播动画，由 play_phase_requests 保证 0.6s 间隔天然串行）。
- **关键**：`apply` 是 `Callable(card: Card) -> String`，同步改该卡数据并返回飘字文本（空串=无变化不飘）。
- **数据推迟进 request 的 execute**：`_execute` 循环不再同步改数据 → `_make_wild_fired_callback` 在 on_fired 时比对快照发现「未变化」→ 批量 `_update_ui` 自动 no-op，无需改它。
- **迁移的 5 个效果**：effect_1001（连锁引爆，ON_SETTLE_STEP）、effect_L9001（你先别急）、effect_L9005/L9006/L9007（预结算批量，仅 ON_PRE_SETTLE 分支）。

### 2. 两 Bug 修复（用户实测回报）
- **飘字丢失**：`_submit_serial_card_effect` 用局部标量 `tip_text` 跨 execute/animate 两个 lambda 写读不可靠（animate 读到空）→ 改用 `tip_holder: Array = [""]`（数组引用类型，`[0]` 原地改必然同步）。
- **末尾牌位不受影响**：末位牌的 request animate 启动数字滚动（≈0.35s）后立即返回 → `play_phase_requests` 结束 → `_refresh_slots_ui()` 对所有卡 `_update_ui()`，而 `_update_ui` 无条件 `_number_tween.kill()` → 末位牌滚动 0s 被掐断，标签冻在旧值（数据其实已改）。**修复**：animate 里 `await tree.create_timer(0.4).timeout` 等滚动播完再返回；卡间 `gap_after` 收紧 0.2s（合计≈0.6s 贴合原飘字节奏）。
- **阶段超时**：批量逐个播放较慢，`_apply_pre_settle_mods` 与 `_execute_wild_card_phase` 的 `play_phase_requests()` 放宽为 `play_phase_requests(20.0)`，防 5s 超时把后段卡的数据变更跳掉。

### 3. 王牌结算重复飘名消除
- **问题**：结算阶段每张王牌飘两次名字——阶段开始时在 (0,0)（`wild_node.global_position` 是节点原点，结算前是 0,0），效果结算后在 EffectNode 位置（带颜色）。用户要「显示名字 → 效果结算 → 下一个」只飘一次。
- **修复**：
  - `SettlementSequencer.gd` 新增 `current_phase` 跟踪（`emit_phase` 记录、`play_phase_requests` 结束清空，防跨阶段误判）。
  - `BaseWildEffect.show_self_tip`：`current_phase == Phase.WILD_CARD && text == get_wild_name()` → 直接 return（名字已在阶段开始显示过；自定义文本如「初始底数+N」不受影响）。
  - `PlayField._execute_wild_card_phase` 名字显示改用 `effect.global_position`（卡面中心）、`FileManager.get_wild_config()`（兼容试炼王牌 9xxx，原 `wild_id_mapping.get` 对 9xxx 返回空→试炼牌根本不飘名）、颜色经 `WildCardUI.COLOR_NAMES` 映射（bbcode 要 "red" 非 "R"，否则飘成白色）。

### 5. 双击判定窗口参数（double_click_window）
- `GameData.double_click_window: float = 0.2`（秒），与 settle_tempo 同模式：`_ready` 独立读 `game/double_click_window`，setting.gd 默认值+同步，debug `/dclick <秒>` 设置并持久化
- 统一接入 7 处双击/双击窗口：
  - 4 个 goods 脚本（goods_pack/magic/event/wild_card）：删 `const DOUBLE_CLICK_WINDOW`，`_double_click_timer = GameData.double_click_window`（倒计时式 _process 递减）
  - StartMenu 退出游戏 / 删除存档：`create_timer(0.3)` → `create_timer(GameData.double_click_window)`（原 0.3s 改默认 0.2s）
  - PlayField 空格双击结算：删 `const SPACE_DOUBLE_TAP_WINDOW=0.3`，比较改为 `GameData.double_click_window`
- UI 滑条用户后续补（handler 写 `_config.set_value("game","double_click_window",v)` + `_save()`）

### 4. 游戏节奏系数系统（settle_tempo）
- 新增 `GameData.settle_tempo: float`（时间倍率，>1 更慢，默认 1.0），`GameData._ready` 独立读 `user://settings.cfg` 的 `game/settle_tempo`（与 setting.gd UI 解耦）
- 全部结算/回合延迟点统一 `delay * settle_tempo`：
  - `SettlementSequencer.play_phase_requests`：gap（`DEFAULT_INTER_GAP`/`gap_after`）+ 阶段超时
  - `BaseWildEffect._submit_serial_card_effect`：滚动等待 0.4、卡间 0.2
  - `PlayField`：抽牌→WAIT 0.5、回合结束→下回合 0.25、PRE_MATH_WAIT、CARD_EFFECT_INTERVAL、SETTLE_BEGIN_INTERVAL、SWAP_POST_DELAY
  - `SettlementAnimator`：ANIM_PEAK、SPAWN_INTERVAL、计数时长、缩小时长
- setting.gd 默认值 + `_apply_to_widgets` 同步已加；**UI 滑条用户手动补全**（handlers 连 `GameData.settle_tempo` + `_config.set_value("game","settle_tempo",v)` + `_save()`）
- debug `/rhythm <倍率>` 设置并持久化到 settings.cfg（范围 0.1-5.0），无参显示当前值

## 关键设计决策
- 串行化靠复用 `AnimationRequest`（execute 改数据 + animate 播动画 + gap 间隔），不新增时序系统
- 集中式抑制（show_self_tip 内判断阶段+文本）优于逐文件删 show_self_tip——自定义飘字/预结算/单卡触发路径不受影响
- `card.get_tree()` 加 `is_instance_valid` + tree 判空守卫，防结算中断时崩溃
